# 本地 OCR 验证

验证日期：2026-10-19。执行环境为 Windows、Visual Studio 自带 C# 编译器、.NET Framework 4.8。

本组测试使用真实 RapidOCR-json v0.2.0 进程及 PP-OCRv4 简中英文模型，输入是测试程序绘制的截图样本。没有调用网络 API，也没有用 mock 替代识别结果。它证明这些样本和生命周期行为通过，不能推导为任意图片均准确。

## 可复现命令

```powershell
.\tools\fetch-ocr.ps1
.\tests\ocr-local.ps1
```

默认运行时目录：`C:\Dev\Tools\RapidOCR\portable-v4`。部署时将此目录的内容放入主程序旁的 `ocr` 目录。官方下载包和保留文件的 SHA256 记录在 `assets/ocr-manifest.json`。

## 修复前后的证据

先增加测试，模块不存在时测试失败。实现后基础样本通过。

随后增加 560×18000 长图样本：原先将整图限制到 4096 长边时，真实引擎返回空结果。改为在同一引擎进程内按 3072px 切片识别，相邻切片重叠 192px，并按检测框中心归属合并后，该样本通过。文字框偏移回原图，因此后续翻译与打码可直接使用真实像素坐标。

## 范围与限制

- 当前随包模型为 PP-OCRv4 简中英文模型，未声称使用或验证 PP-OCRv5/v6。
- OCR 可能合并英文空格；测试中深色混排实际输出了 `Darkmode20261019`。手写体、复杂艺术字、低清晰度与任意旋转布局未做准确率基准。
- 四点检测多边形转为轴对齐 `RectangleF`，并裁剪到原图范围；没有输出逐字坐标。
- 为控制内存，总像素上限 4000 万。实现有 60 秒总超时；本组没有故意等待 60 秒进行超时故障注入。
- 输入图片通过内存 PNG/base64 进入标准输入，不写临时截图、不记录原始识别文字到应用日志。测试样本与测试文本是显式的验证产物。
